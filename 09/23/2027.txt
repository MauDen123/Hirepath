● Based on the code review, the primary issue causing the Internal Server Error
  when changing vacancy status in the HRMO interface is a bug in the vacancy
  edit form (src/app/vacancies/[id]/edit/form.tsx) related to how numeric fields
  are initialized and parsed.

  Root Cause Analysis

  Critical Bug in Form Initialization

  In the form's useState initialization (lines 53-69), numeric fields are
  initialized using nullish coalescing (??) with empty strings:
  salaryGrade: vacancy.salaryGrade ?? '',
  slots: vacancy.slots ?? '',

  Problem: When vacancy.salaryGrade or vacancy.slots is 0 (a valid value), the
  expression evaluates to '' because 0 is falsy in JavaScript. This causes:
  1. Form displays empty input for fields that should show "0"
  2. On submit, parseInt('') returns NaN for these fields
  3. Prisma receives NaN for non-nullable integer fields (salaryGrade, slots)
  4. Database operation fails with Internal Server Error

  Additional Issues in Submit Handler

  In the handleSubmit function (lines 113-116), the conversion logic has gaps:
  salaryGrade: parseInt(formData.salaryGrade, 10),
  slots: parseInt(formData.slots, 10),
  - No protection against empty strings (becomes NaN)
  - No protection against non-numeric strings
  - Uses parseInt without radix validation (though radix 10 is provided)

  Recommended Fixes

  1. Fix Form Initialization

  Replace nullish coalescing with safe string conversion:
  salaryGrade: vacancy.salaryGrade?.toString() ?? '',
  slots: vacancy.slots?.toString() ?? '',

  2. Improve Submit Validation

  Add validation before parsing:
  const parsedSalaryGrade = formData.salaryGrade.trim() === ''
    ? undefined
    : parseInt(formData.salaryGrade, 10);
  const parsedSlots = formData.slots.trim() === ''
    ? undefined
    : parseInt(formData.slots, 10);

  // Add validation
  if (formData.salaryGrade.trim() !== '' && isNaN(parsedSalaryGrade)) {
    throw new Error('Salary Grade must be a valid number');
  }
  if (formData.slots.trim() !== '' && isNaN(parsedSlots)) {
    throw new Error('Slots must be a valid number');
  }

  // In the body:
  salaryGrade: parsedSalaryGrade,
  slots: parsedSlots,

  3. Consider Client-Side Validation

  Add min attributes to prevent invalid inputs:
  <input
    type="number"
    name="salaryGrade"
    min="0"
    // ... other props
  />
  <input 
    type="number" 
    name="slots"
    min="0" 
    // ... other props
  />

  2. Edit the vacancy in HRMO interface
  3. Change only the status field (leave other fields unchanged)
  4. Submit the form
  5. Verify the update succeeds without Internal Server Error
  6. Confirm the vacancy retains its original salaryGrade and slots values (0)

  Additional Notes

  - The status field handling appears correct (no conversion needed)
  - Monthly salary and validity months are properly handled (nullable fields)
  - Publication channels and date conversions look appropriate
  - This fix addresses the core bug that would affect ANY vacancy with 0 in
